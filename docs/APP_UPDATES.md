# 应用内更新与播放体验改进

版本：`1.8.15-android.5-tv` / versionCode `5`，2026-11-16。

## 用户操作

1. 本版首次仍需安装一次，因为旧版本没有更新器；覆盖升级必须使用原签名。
2. 以后在设置中检查更新，或等待启动时每天一次的自动检查。
3. 查看版本说明，选择“下载并更新”。系统 DownloadManager 下载，可退出页面继续；更新网络失败不会占用播放线程池。
4. 前台下载完成并通过校验后，应用打开安装流程；后台完成则返回更新页选择“安装更新”。普通应用不能跳过系统安装确认。Android 8+ 首次可能需要允许“安装未知应用”；有些电视固件还会额外阻止第三方安装。
5. 取消安装不会删除用户资料，也可在更新页重新安装。包文件被系统清理后需要重新下载。

不申请 Root、不使用无障碍模拟确认、不强制卸载旧版。没有原签名就不能承诺无损覆盖安装。

## 发布与部署

更新目标为 `cxapython/tvbox-arm`，**不是 Apple 上游**。应用通过 GitHub latest release API 选择正式、非草稿、非预发布的 Release，从中读取 `update.json` 和同版本 APK。

每次正式发布必须同时增加 `app/build.gradle` 中的 `versionCode` 和 `versionName`，例如本版为 5 / 1.8.15-android.5-tv。应用用 versionCode 判断新旧，不按版本字符串排序。

构建脚本在签名和 ARM32 校验后，从实际 APK 用 aapt/apksigner 提取包名、版本、最低系统版本和证书；生成 update.json，并把 APK 与 JSON 的哈希写入 SHA256SUMS。Release 先以草稿上传三个附件，最后才公开，避免检查到半成品。

固定附件名：

```text
yingxia-tv-arm32.apk
update.json
SHA256SUMS
```

无需手工维护在线版本号或另建更新服务器。不要手工把别的 APK 替换到同版本附件中。

### 固定签名是必须的

GitHub 仓库的 Actions Secrets：

| 名称 | 必填 | 内容 |
| --- | --- | --- |
| ANDROID_KEYSTORE_BASE64 | 是 | **现有安装包对应**的 keystore 的 Base64 内容 |
| ANDROID_KEY_ALIAS | 是 | keystore 别名 |
| ANDROID_STORE_PASSWORD | 是 | keystore 密码 |
| ANDROID_KEY_PASSWORD | 是 | 私钥密码 |
| ANDROID_CERT_SHA256 | 建议 | 期望的证书 SHA-256 指纹，防止配置错密钥 |

本地默认使用 `~/.android/debug.keystore`。只有电视当前应用本来就用它签名时，把同一份密钥配置到 CI 才能连续覆盖安装。它不是上一份线上包的签名密钥的替代品。

本次实际比对发现，已发布 android.4 的证书与本机默认签名不同：

```text
GitHub android.4: 43d11a24b091ee2f2f4af966f026db286a603a55e2a74923f0f80682314a86b8
本机默认开发证书: 970d1d004420ac9946c38bd3d173bb4d29750b3d4199193de5029b1623b76975
```

这只能证明两份包签名不同，**不能据此判断用户电视实际装的是哪份包**。需要确认电视已装 APK 的证书并保留对应私钥。如果当时使用了未保存的临时签名，无法从 APK 恢复私钥；应先导出备份，再由用户决定首次迁移方案，不能静默卸载。

没有固定签名 Secrets 时，新 workflow 仍可完成测试和构建，但会明确警告且跳过 release job；临时签名包只作为验证 Artifact，不进入应用更新渠道。PR 总是使用临时开发签名。

### workflow 修复

本次读取的最近两次失败运行：43049625095、43025575920。

- build job 成功，单测、Lint、构建、签名和 ABI 校验步骤均成功；release job 失败。

- 新脚本重复发布已公开版本时直接成功跳过，不改标签、不覆盖附件。
- 同提交的草稿/未完整发布可重试；既有标签指向不同源码时明确拒绝，要求新版本。
- 正式发布检查数值 versionCode 递增、标签与版本一致、附件哈希一致。

上述诊断与本地验证完成时尚未推送。提交后的线上结果以 GitHub Actions 为准；本次没有读取或改动远程 Secrets。

## 安全校验

- 元数据来源限定为本项目 GitHub Release HTTPS 附件，不接受任意 URL、自定义更新服务器或 Apple 安装包。
- 元数据有 schema、字段和大小限制；APK 上限 100 MiB；要求包名与 ARM32 ABI 正确。
- 下载后先拷贝到私有缓存，再校验该私有副本的大小、SHA-256、真实包名/版本、真实证书、最低系统版本及 ARM32 库。
- 清单证书必须匹配当前已装应用，实际 APK 证书又必须匹配清单。
- 安装前再次完整校验，不以“以前下载成功”替代当前校验。
- FileProvider 不导出，仅分享独立 updates 缓存目录，并给系统安装器临时读权限；不分享资料库、订阅、Cookie 或通用文件根目录。
- Android 5–7 使用系统安装器的安全设置；Android 8+ 检查应用安装授权。
- GitHub 不可达、限流、没有 update.json 或固件不支持安装时给出提示；不使用不可信镜像绕过校验。

## 同批播放改进

- M3U EXTINF 请求头；默认头 → EXTINF → EXTVLCOPT → URL 指定头，后者覆盖前者，不串到下一频道。
- 同分组同名频道归并备用线路，频道列表与线路列表分开；坏线路/缓冲 20 秒自动换线，每条备用线只尝试一次，避免循环。失败后保留现有有限重试；可在设置关闭自动切线。
- 音轨与字幕按语言/名称恢复，不复用上一集的轨道索引；“关闭字幕”也会记住。
- 快进/后退支持 5 / 10 / 15 / 30 / 60 秒，控制栏和遥控器一致。
- 下一集只提前解析地址，不预下载整集、不增加解码器。短集开始后约 5 秒、长集末尾约 30 秒触发；同一请求复用、约 5 分钟过期、换集/离页取消；可关闭。
- 酷我/咪咕及 Musify/Audius/Jamendo 的无目录歌词尝试 QQ/网易云同录音匹配；某目录失败继续尝试另一目录，严格匹配版本、歌手和时长，不替换当前音频。

## 验证边界

单测覆盖更新描述、URL 限制、数值版本、换线边界、请求头、字幕偏好匹配、预解析复用/过期和歌词回退。脚本离线测试覆盖已发布版本跳过、草稿恢复、先上传后公开、标签冲突、哈希失败和 versionCode 未递增。

Android 12 / API 31 TV 模拟器进行了实际 PackageManager 归档、证书、哈希和 FileProvider 测试，并验证视频解码与坏直播线路回退。该模拟器是 ARM64-only，测试包额外包含 ARM64；归档校验单独测试，**正式 ARM32 安装资格检查仍会拒绝该模拟器**。测试用更高版本同签名惰性 APK 从未安装，不能把归档校验通过宣传为完整的 ARM32 覆盖安装已实测。

未连接 ARM32 小米电视；未验证该电视系统的安装确认界面、GitHub 网络可达性和真实升级。本地验证不包含新版 GitHub Actions 的线上结果；固定签名配置和首次签名衔接仍需部署时确认。
